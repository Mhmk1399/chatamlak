# تحویل اسپرینت ۴ گفتگوی اوج

تاریخ: ۲۰۲۶-۱۱-۲۳

وضعیت: **در مخزن Chat پیاده‌سازی و به‌صورت محلی تأیید شده است**. این تحویل ادعای پایداری تولید یا تکمیل مسیر مرورگری مستقرشدهٔ Web ↔ Chat را ندارد.

گفتگوی اوج همچنان مالک گفتگوها، پیام‌ها، عضویت، وضعیت تحویل/خواندن، پرونده‌های پشتیبانی و مجوز realtime است. Owj Web مرجع هویت انسانی و CRM باقی می‌ماند. یکپارچه‌سازی فقط از قراردادهای HTTP احرازشده استفاده می‌کند و Chat مجموعه‌های پایگاه‌دادهٔ Web را نمی‌خواند یا نمی‌نویسد.

## محدودهٔ تحویل‌شده

| بخش | وضعیت پیاده‌سازی | قرارداد |
|---|---|---|
| احراز هویت Chat بومی | جریان authorization code وب با PKCE، state، تراکنش یک‌بارمصرف سمت سرور، نشست مات Chat و بازاعتبارسنجی وضعیت جاری | [SSO بومی با Web نسخه ۱](./CHAT_NATIVE_WEB_SSO_V1.md) |
| سازگاری محلی | `/api/login` و `/api/register` فقط در حالت غیرتولیدی `OWJ_CHAT_NATIVE_AUTH_MODE=local_test` باقی مانده‌اند؛ startup تولید این حالت را رد می‌کند و رابط آن را حالت آزمایشی بومی می‌نامد | [SSO بومی با Web نسخه ۱](./CHAT_NATIVE_WEB_SSO_V1.md) |
| پیوند هویت | پیوند دقیق موجود استفاده می‌شود؛ برای subject تأییدشدهٔ جدید یک حساب جدا در Chat ساخته می‌شود. تطبیق خودکار نام کاربری/ایمیل یا ادغام ضمنی وجود ندارد | [SSO بومی با Web نسخه ۱](./CHAT_NATIVE_WEB_SSO_V1.md) |
| چرخهٔ پشتیبانی | نسخهٔ ۲ افزایشی برای exchange/logout نشست محدود، جاری/تاریخچه، پروندهٔ جدید، بازگشایی، پیام، replay و پیوند صریح تاریخچهٔ مهمان | [چرخهٔ پشتیبانی نسخه ۲](./CHAT_SUPPORT_LIFECYCLE_V2.md) |
| سازگاری پشتیبانی | مسیرهای نسخهٔ ۱، scope ثابت کوکی `/support/v1` و رفتار SSE/WebSocket موجود بدون تغییر می‌مانند | [API پشتیبانی نسخه ۱](./CHAT_SUPPORT_API_CONTRACT_V1.md) |
| CRM | عضو فدره‌شدهٔ Chat با اثبات نمایندگی می‌تواند از Web ساخت وظیفهٔ محدود را بخواهد؛ Chat هیچ تغییر CRM وب را محلی ذخیره نمی‌کند | [یکپارچه‌سازی وظیفهٔ CRM نسخه ۱](./CHAT_CRM_TASK_INTEGRATION_V1.md) |
| تماس | WebRTC واقعی دوکاربره در Chromium روی loopback به‌همراه پوشش سرور و مؤلفه | [گزارش E2E تماس](./CHAT_CALL_E2E_REPORT.md) |

منبع همچنین نسخهٔ ۳ schema را برای `native_web_auth_transactions`، شامل انقضا و ایندکس یکتای digest حالت، اضافه می‌کند. UUIDهای فعلی Chat و نویسندگی تاریخی بازنویسی نمی‌شوند.

## مرز امنیتی

- PKCE verifier، digestهای state و browser token، اعتبارنامه‌های سرویس Web و اثبات نمایندگی CRM در سمت سرور می‌مانند. JWT یا service token وب هرگز به مرورگر Chat برگردانده نمی‌شود.
- تراکنش مجوز پس از پنج دقیقه منقضی و فقط یک‌بار مصرف می‌شود. کوکی‌های host-only با `HttpOnly` و `SameSite=Lax` تراکنش و نشست Chat را مقید می‌کنند؛ در HTTPS تولید `Secure` هستند.
- نشست فدره‌شده با سقف cache مجوز ۶۰ ثانیه در Web بازاعتبارسنجی می‌شود. لغو قطعی نشست محلی را حذف می‌کند؛ خطای گذرای upstream درخواست را fail-closed می‌کند ولی به‌دروغ هویت را لغوشده نمی‌نامد.
- تماس فدره‌شده به `chat:call` نیاز دارد. پس از اصلاح guard تماس، enforce شدن scope با regression test تأیید شد. `chat:admin` وب نقش admin/owner بومی Chat را اعطا نمی‌کند.
- CRM فقط allowlist صریح را می‌پذیرد و فیلدهای پیام، transcript، تماس، مشتری، تلفن و ناشناخته را رد می‌کند. محتوای پیام ارسال نمی‌شود.
- پشتیبانی نسخهٔ ۲ هر عملیات پرونده/پیام را با هویت پشتیبانی مجاز می‌کند و در عملیات تعریف‌شده کلید idempotency پایدار می‌خواهد.

| پوشش امنیتی تکمیلی | رد نشست/هویت و جداسازی/چرخهٔ پشتیبانی در مجموعه‌های کامل بالا موفق بود |

در بررسی محلی مسیرهای هویت، رسانهٔ خصوصی، دسترسی مستقیم container/object-store، تکمیل بارگذاری و صف، یافتهٔ P0 جدیدی مشاهده نشد. این نتیجه شواهد آزمایشی محدود است و گواهی امنیت تولید نیست.

پس از مشخص شدن نبود executable فایرفاکس در cache محلی، Firefox دوباره اجرا نشد؛ نتیجهٔ مرورگر فقط برای Chromium است. ابزار `graphify` در محیط موجود نبود، بنابراین artifact گراف ساخته نشد. این کمبود ابزار جای بررسی قرارداد یا اجرای تست را نگرفته است.

## مرز پذیرش و کار باقی‌ماندهٔ استقرار

این شواهد رفتار مخزن را در محیط آزمایش‌شده ثابت می‌کنند، نه پایداری تولید. پیش از پذیرش تولید:

1. مسیر کامل مرورگری و مستقرشدهٔ میان دو مخزن را با proxy، کوکی‌ها، endpointهای authorize/exchange/status وب، widget پشتیبانی و endpoint CRM واقعی اجرا کنید.
2. HTTPS/TLS و اعتبارنامه‌های TURN تولید را تنظیم و تماس را روی NAT/firewall محدود و شرایط reconnect/failure تأیید کنید. اسکریپت محلی عمداً ICE server ندارد و TURN یا عبور اینترنتی را ثابت نمی‌کند.
3. rotation توکن سرویس، سیاست proxy/header، rate limit، پایش، restore/rollback و رفتار منابع تولید را تأیید کنید.
4. مسیر سازگاری غیرتولیدی `local_test` و پشتیبانی نسخهٔ ۱ را تا تصمیم صریح و جداگانه برای بازنشستگی حفظ کنید.
