# اسکریپت نصب

اسکریپت نصب (`ouj-chat-deploy`) ابزاری تعاملی و مبتنی بر منو برای وابستگی‌ها، بیلد، Nginx، گواهی SSL، تنظیم محیط، مدیریت پایگاه داده و به‌روزرسانی است. منوها به نسخهٔ نصب‌شدهٔ اسکریپت بستگی دارند. برای این شاخهٔ MongoDB، [راهنمای فعلی MongoDB](./MongoDB.md) را دنبال کنید و پیش از اجرای سرور، محیط تولیدشده را بررسی کنید.

:::info

این اسکریپت برای Ubuntu (22.04+) هدف‌گذاری شده و به دسترسی root نیاز دارد (هنگامی که به‌عنوان root اجرا نشود، به‌طور خودکار از `sudo` استفاده می‌کند). برای راه‌اندازی‌های مبتنی بر Docker یا کاملاً دستی، به [نصب از طریق Docker](./Installation-Docker.md) و [نصب دستی](./Manual-Installation.md) مراجعه کنید.

:::

## اولین اجرا

سورس بررسی‌شدهٔ گفتگوی اوج را از مسئول استقرار دریافت کنید. سپس از ریشهٔ مخزن روی سرور اجرا کنید:

```bash
bash scripts/install.sh
```

این دستور اسکریپت محلی را اجرا می‌کند، منو را باز می‌کند و دستور سراسری `ouj-chat-deploy` را نصب می‌کند. از آن پس، هر زمان که خواستید آن را با این دستور اجرا کنید:

```bash
ouj-chat-deploy
```

## روند نصب

هنگامی که **Install** را انتخاب می‌کنید، اسکریپت شما را از طریق مجموعه‌ای از پرسش‌ها راهنمایی می‌کند:

### ۱. حالت منبع

| حالت | توضیح |
|---|---|
| GitHub | کلون‌کردن پروژه از مخزن رسمی GitHub. |
| Offline | نصب از یک فایل zip منبع محلی (برای سرورهای محدود شده مفید است). |

### ۲. حالت نصب

| حالت | توضیح |
|---|---|
| Domain | سرویس دهی گفتگوی اوج روی یک نام دامنه (مانند `example.com`). |
| IP | سرویس دهی مستقیم گفتگوی اوج روی IP عمومی سرور. |

### ۳. حالت گواهینامه

| حالت | توضیح |
|---|---|
| Obtain certificate | درخواست خودکار گواهینامه. برای دامنه ها از Certbot (Let's Encrypt) استفاده میکند؛ برای IPها یک گواهینامه کوتاه مدت ۶ روزه از طریق `lego` درخواست میکند. |
| TLS certificate files | استفاده از فایل های `fullchain.pem` و `privkey.pem` موجود خودتان. |
| HTTP only | رد کردن TLS و سرویس دهی روی HTTP ساده. |
| Self-signed certificate | تولید یک گواهینامه خودامضاشده (Self-signed). توصیه نمیشود. |

:::info

HTTPS برای اعلان های Push الزامی است (به جز روی `localhost`). اگر میخواهید Push کار کند، حالتی غیر از HTTP only را انتخاب کنید.

:::

### ۴. تنظیم MongoDB

این شاخه به replica set در دسترس MongoDB یا استقرار مناسب Atlas نیاز دارد. پیش از اجرای سرور، `MONGODB_URI` را خصوصی و `MONGODB_DATABASE=ouj_chat` را تنظیم کنید؛ URI در `.env.example` عمداً خالی می‌ماند. راه‌اندازی replica set و ورود صریح دادهٔ قدیمی در [MongoDB](./MongoDB.md) آمده است.

نسخه‌های قدیمی اسکریپت نصب گزینهٔ SQLite یا PostgreSQL داشتند. آن‌ها نصب SQL قدیمی را توصیف می‌کنند و دیتابیس اجرای فعلی را انتخاب نمی‌کنند. نسخهٔ اسکریپت و محیط خروجی را بررسی کنید؛ ساخت خودکار MongoDB یا ورود خودکار داده را فرض نکنید.

### ۵. پرسش های محیط

در حین نصب، اسکریپت تنظیمات اصلی را می‌پرسد و آن‌ها را در `.env` می‌نویسد:

| پرسش | متغیر محیطی | پیش‌فرض |
|---|---|---|
| پورت سرور | `SERVER_PORT` | `5174` |
| پورت کلاینت | `CLIENT_PORT` | `80` |
| پورت Media Worker | `WORKER_PORT` | `8080` |
| ایمیل برای اطلاعیه‌های Let's Encrypt (حالت certbot) | — | — |

کلیدهای رمزنگاری و push نوتیفیکیشن (`STORAGE_ENCRYPTION_KEY`، `VAPID_*`) به‌طور خودکار تولید می‌شوند. فهرست کامل متغیرهایی که می‌توانید بعداً تنظیم کنید در [متغیرهای محیطی](./Environment-Variables.md) قرار دارد.

### ۶. راه اندازی رله Coturn TURN/STUN (اختیاری)

گفتگوی اوج از تماس های صوتی و تصویری از طریق WebRTC پشتیبانی میکند. هنگامی که کاربران پشت NATهای متقارن (Symmetric NAT) یا فایروال های محدودکننده قرار دارند، برای برقراری ارتباط نظیر به نظیر (P2P) به یک سرور رله TURN/STUN نیاز است.

اسکریپت نصب میتواند به طور خودکار یک سرور اختصاصی [Coturn](https://github.com/coturn/coturn) را روی همان سرور نصب و پیکربندی کند.

### ۷. ایجاد کاربر مالک در اولین اجرا

پس از تکمیل نصب و شروع سرویس، در اولین دسترسی از شما خواسته می‌شود که یک کاربر مالک ایجاد کنید. این حساب مالک دسترسی کامل به پنل مدیریت برای مدیریت کاربران، چت‌ها و تنظیمات سیستم دارد. برای جزئیات به [پنل مدیریت](./Admin-Panel.md) مراجعه کنید.

## زیرمنوی پایگاه داده

گزینهٔ **۵** مدیر پایگاه دادهٔ نسخهٔ نصب‌شدهٔ اسکریپت را باز می‌کند. جدول زیر گروه‌های منوی تاریخی را توصیف می‌کند؛ وجود یک گزینه به‌معنای پشتیبانی آن از MongoDB نیست. برای پشتیبان‌گیری، بازیابی آفلاین، ورود داده و بررسی MongoDB از [دستورات فعلی پایگاه داده](./Database-Commands.md) استفاده کنید. تا زمانی که پشتیبانی منوی نصب‌شده از MongoDB بررسی نشده، حساب‌ها و گفتگوها را از پنل مدیریت اداره کنید.

| گروه | اقدام‌ها |
|---|---|
| Inspect | خلاصه پایگاه داده، چت‌ها، کاربران، فایل‌ها |
| Backup & Repair | پشتیبان‌گیری، بازیابی، vacuum، بازنشانی، حذف |
| User & Chat Management | ایجاد کاربر، تولید کاربران، ویرایش کاربر، مسدود/رفع‌مسدود، ایجاد گروه/کانال، افزودن اعضا، ویرایش چت |
| Remote Channels | پیکربندی کانال ریموت |
| Destructive Actions | حذف چت‌ها، حذف کاربران، حذف فایل‌ها |
| Help & Navigation | نمایش راهنما، بازگشت، خروج |

## به‌روزرسانی و دانگرید

از منوی اصلی گزینه **Update گفتگوی اوج** (گزینه ۲) را برای به روزرسانی یا دانگرید نمونه خود انتخاب کنید:

روند زیر منوی نصب را توصیف می‌کند. بازگشت از MongoDB به نسخهٔ SQL به کد قدیمی سازگار و پشتیبان SQL همان نسخه نیاز دارد؛ منو دادهٔ MongoDB را به SQL برنمی‌گرداند. پیش از عبور میان این دو نسل دیتابیس، [به‌روزرسانی و دانگرید](./Updating.md) را دنبال کنید.

۱. **پشتیبان گیری از پایگاه داده**: اسکریپت پیش از تغییر فایل های برنامه، پیشنهاد ایجاد یک نسخه پشتیبان با برچسب زمانی را میدهد.

۲. **حالت GitHub**:

   - **به روزرسانی**: اگر به روزرسانی جدیدی روی `origin/main` موجود باشد، اسکریپت به طور خودکار آن را دریافت (`git pull --ff-only`)، وابستگی ها را نصب، مهاجرت های دیتابیس را اعمال و سرویس ها را مجدداً راه اندازی میکند.
   - **دانگرید**: اگر مخزن از قبل به روز باشد، پیام `Do you want to downgrade? [y/N]` نمایش داده میشود. در صورت تأیید، می‌توانید هر نسخه معتبری را مشخص کنید (تگ نسخه بندی معنایی مانند `v0.11.4`، تگ سفارشی، شاخه یا هش کامیت). اسکریپت آن مرجع را checkout کرده، مهاجرت ها را انجام میدهد و پروژه را بازسازی میکند.

۳. **حالت آفلاین**:

   - **به روزرسانی**: اگر فایل `VERSION` درون آرشیو zip جدیدتر از نسخه نصب شده باشد، فایل ها را به روزرسانی و پروژه را مجدداً بازسازی میکند.
   - **دانگرید**: اگر مقدار `VERSION` درون آرشیو یکسان یا قدیمی تر از نسخه نصب شده باشد، پیش از دانگرید از شما تأییدیه میگیرد.

برای جزئیات کامل و روش های دستی به [به‌روزرسانی و دانگرید](./Updating.md) مراجعه کنید.

## به روزرسانی منوی اسکریپت

برای به روزرسانی خودِ اسکریپت `ouj-chat-deploy`، گزینه **Update menu** (گزینه ۷) را انتخاب کنید:

۱. **بررسی به روزرسانی ها**: اسکریپت به مخزن رسمی GitHub متصل میشود تا بررسی کند آیا نسخه جدیدتری از `scripts/install.sh` موجود است یا خیر.

۲. **به روزرسانی خودکار**: در صورت وجود نسخه جدیدتر، به طور خودکار آن را دانلود کرده و دستور سراسری `ouj-chat-deploy` (`/usr/local/bin/ouj-chat-deploy`) را به آخرین نسخه به روزرسانی میکند.

۳. **درخواست نصب مجدد**: اگر منو از قبل به روز باشد، یا در صورتی که بررسی GitHub با خطا مواجه شود (برای مثال در شبکه های دارای محدودیت اتصال)، این پیام نمایش داده میشود:

   ```txt
   Do you want to reinstall the current menu again? [y/N]
   ```
   انتخاب `yes` دستور سراسری را با استفاده از اسکریپت محلی فعلی مجدداً نصب میکند.

## mirrorها برای شبکه‌های محدودشده

اگر سرور شما دسترسی محدودی به منابع پیش‌فرض بسته‌ها دارد، از **Configure mirrors** برای تنظیم موارد زیر استفاده کنید:

| mirror | هدف |
|---|---|
| NodeSource mirror | منبع جایگزین برای راه‌اندازی apt مربوط به Node.js. |
| apt mirror source | mirror اضافه apt برای بسته‌های پایه. |
| npm registry mirror | رجیستری جایگزین npm برای نصب وابستگی‌ها. |

همچنین می‌توانید از همان منو پیش‌فرض‌ها را بازگردانی کنید (پاک‌کردن همه mirrorها).

:::tip

می‌توانید از این mirrorها در محیط محدودشده ایران استفاده کنید:
- NodeSource:
```
https://mirror-nodejs.runflare.com/dist/v24.22.1/node-v24.22.1-linux-x64.tar.gz
```
- APT:
```
http://ubuntu.pars.host/ubuntu/
```
- NPM:
```
https://package-mirror.liara.ir/repository/npm/
```

:::

## لاگ‌ها

زیرمنوی **View Logs** مفیدترین لاگ‌ها را بدون نیاز به به‌خاطر سپردن مسیرها در دسترس قرار می‌دهد:

| گزینه | منبع |
|---|---|
| Script logs | لاگ خود نصاب در `/opt/ouj-chat/logs/install.log`. |
| Service logs | خروجی `journalctl` برای `ouj-chat.service`. |
| Nginx access logs | لاگ دسترسی Nginx. |
| Nginx error logs | لاگ خطای Nginx. |

برای اطلاعات بیشتر درباره تشخیص مشکلات، به [عیب‌یابی](./Troubleshooting.md) مراجعه کنید.
