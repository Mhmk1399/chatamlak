# پنل مدیریت

پنل مدیریت یک رابط مبتنی بر وب برای مدیریت کاربران، چت‌ها، تنظیمات زمان اجرا و عملیات سیستم فراهم می‌کند. برای کاربران با نقش **مالک** (owner) یا **مدیر** (admin) قابل دسترسی است.

## نقش‌های کاربر

- **Owner (مالک)**: دسترسی کامل به پنل مدیریت و همه قابلیت‌ها
- **Admin (مدیر)**: دسترسی محدود به پنل مدیریت
- **User (کاربر)**: کاربر عادی بدون دسترسی مدیریتی

:::warning

فقط یک کاربر با نقش مالک می‌تواند وجود داشته باشد.

:::

## دسترسی به پنل مدیریت

دو روش اصلی برای اعطای نقش **مالک** (owner) یا **مدیر** (admin) به یک حساب کاربری وجود دارد:

### روش ۱: CLI بومی (VPS و محیط دارای ترمینال)

1. از ریشهٔ مخزن، نحو فعلی فرمان را بررسی کنید:

   ```sh
   npm --prefix server run db:user:create -- --help
   npm --prefix server run db:user:edit -- --help
   ```

2. حساب را با فیلدهای لازم و نقش موردنظر ایجاد کنید یا حساب موجود را ویرایش کنید. برای نمونه، **پس از توقف همهٔ نویسندگان**، نقش مدیر را به یک حساب موجود بدهید:

   ```sh
   npm --prefix server run db:user:edit -- your_username --role admin --offline
   ```

   اگر سرور محلی در حال اجراست، `--offline` را حذف و `ADMIN_API_TOKEN` را خصوصی تنظیم کنید تا CLI از API مدیریت استفاده کند. فرمان‌ها آرگومان می‌پذیرند و پرسش‌های تعاملی اسکریپت‌های SQL تاریخی را ندارند. پشتیبانی منوی نصب به نسخهٔ نصب‌شدهٔ آن بستگی دارد.

3. اگر برنامه متوقف است آن را اجرا کنید، با حساب ارتقایافته وارد شوید و **پنل مدیریت** را از نوار کناری باز کنید. رفتار آنلاین و آفلاین در [دستورهای دیتابیس](./Database-Commands.md) آمده است.

### روش ۲: ارتقای مدیریت اضطراری و مالکان (PaaS و رابط کاربری وب)

برای استقرار روی سرویس دهنده های PaaS (مانند Render، Railway یا Fly.io) یا پلتفرم های کانتینری که دسترسی به ترمینال در آنها در دسترس نیست، کاربران احراز هویت شده میتوانند مستقیماً از طریق رابط کاربری وب دسترسی مدیریت را دریافت کنند:

۱. متغیر محیطی `ADMIN_API_TOKEN` را در تنظیمات سرویس خود (مثلاً داشبورد PaaS) پیکربندی کنید. در صورت عدم تنظیم، Songbird در اولین اجرا توکنی به صورت خودکار تولید کرده و در `.env` ذخیره میکند.

۲. با حساب کاربری ثبت نام شده خود وارد شوید.

۳. مرورگر خود را باز کرده و مستقیماً به آدرس `/admin` بروید.

۴. توکن `ADMIN_API_TOKEN` را در فرم Emergency Admin Access وارد کنید.

۵. روی دکمه **Claim Privileges** کلیک کنید.

:::info قوانین ارتقای نقش ها

- **اولین درخواست (Owner)**: اگر هیچ کاربری در حال حاضر نقش **owner** را نداشته باشد، کاربر درخواست کننده به نقش **owner** ارتقا می یابد.
- **درخواست های بعدی (Admin)**: اگر کاربر owner قبلاً وجود داشته باشد، درخواست های بعدی کاربر را به نقش **admin** ارتقا میدهند.

:::

:::warning الزام HTTPS

ارتقای مدیریت اضطراری نیازمند اتصال امن (HTTPS) یا شبکه محلی (`localhost` یا `127.0.0.1` یا `::1`) است. اتصالات ناامن HTTP روی سرورهای ریموت این قابلیت را مسدود میکنند.

:::

:::danger هشدار امنیتی

به هیچ وجه `ADMIN_API_TOKEN` خود را منتشر نکنید و مخفی نگه دارید. هرکس با استفاده از این توکن میتواند به پنل ادمین دسترسی پیدا کند.

:::

## تب داشبورد

داشبورد یک نمای کلی از برنامه Songbird شما ارائه می‌دهد:

- **آمار**: کل کاربران، چت‌ها، پیام‌ها و فایل‌های آپلودشده
- **اطلاعات سیستم**: زمان فعالیت و محیط
- **فضای ذخیره‌سازی**: اندازه دیتابیس و دایرکتوری آپلود

## تب کاربران

همه کاربران در برنامه Songbird خود را مدیریت کنید:

### قابلیت‌ها

- **مشاهده همه کاربران**: لیست صفحه بندی شده با اندازه صفحه قابل تنظیم
- **ایجاد کاربران**: ایجاد حساب های جدید با نام کاربری، نام مستعار، رمز عبور
- **ویرایش کاربران**:
  - به‌روزرسانی نام کاربری، نام مستعار، آواتار
  - بازنشانی رمز عبور به‌صورت درون‌خطی
  - تغییر نقش کاربر (admin/user)
  - مسدود/رفع مسدودیت کاربران
- **حذف کاربران**: حذف دائمی حساب های کاربری
- **جستجو و فیلتر**: جستجو و فیلتر کردن روی کل مجموعه داده کاربران
- **مرتب سازی**: مرتب سازی بر اساس نام کاربری، نام مستعار، تاریخ ایجاد یا آخرین بازدید

### تکمیل نام نمایشی کاربر جدید از مخاطب

در فرم **کاربر جدید**، کنترل اختیاری **تکمیل از مخاطبین** فقط **نام نمایشی (`nickname`)** را پر می‌کند:

- **انتخاب مخاطب** فقط پس از کلیک شما، انتخاب‌گر مخاطب مرورگر را باز و نام یک مخاطب انتخاب‌شده را درخواست می‌کند. انتخاب مستقیم به HTTPS، صفحهٔ اصلیِ خارج از قاب و پشتیبانی مرورگر نیاز دارد؛ معمولاً Chrome اندروید این امکان را دارد و در آیفون و دسکتاپ تضمین نمی‌شود. [راهنمای Contact Picker در Chrome](https://developer.chrome.com/docs/capabilities/web-apis/contact-picker) را ببینید.
- **فایل مخاطب (.vcf)**، یک vCard با رمزگذاری UTF-8 و حجم حداکثر **۲۵۶ KiB** را محلی می‌خواند. فقط فیلدهای نام `FN` و `N` استفاده می‌شوند؛ فایل دارای چند مخاطب پذیرفته نمی‌شود.

نام نمایشی واردشده را بررسی کنید و اگر از محدودیت تنظیم‌شده بلندتر است، آن را کوتاه کنید. نام کاربری و رمز عبور را خودتان وارد و سپس **ساخت کاربر** را صریحاً انتخاب کنید. انتخاب مخاطب، حساب نمی‌سازد، شماره وارد نمی‌کند و هویت موجودی را تطبیق نمی‌دهد. لغو، منع دسترسی یا مرورگر ناسازگار، مسیر ورود دستی را حفظ می‌کند.

برنامه فایل مخاطب، شماره‌ها یا دفترچهٔ مخاطبین را ارسال یا نگهداری نمی‌کند. فقط نام بررسی‌شده با ثبت صریح همان فرم موجود ساخت کاربر، به‌عنوان نام نمایشی معمولی ارسال می‌شود. API و مجوزهای مدیریتی قبلی همچنان اعمال می‌شوند.

## تب چت‌ها

مدیریت پیام‌های مستقیم، گروه‌ها و کانال‌ها:

### قابلیت‌ها

- **مشاهده همه چت ها**: لیست صفحه بندی شده همراه با نوع، تعداد اعضا، تعداد پیام ها و تاریخ ایجاد
- **ایجاد چت ها**: ایجاد گروه یا کانال جدید
- **ویرایش چت ها**: به روزرسانی متادیتا و مالکیت چت
- **حذف چت ها**: حذف دائمی چت ها و همه پیام های مرتبط
- **جستجو و فیلتر**: جستجو و فیلتر کردن روی کل گروه ها و کانال ها
- **مرتب سازی**: مرتب سازی بر اساس نام، نوع، حریم خصوصی، تاریخ ایجاد، تعداد اعضا یا تعداد پیام ها
- **مدیریت اعضا**: مشاهده و تغییر عضویت چت
- **افزودن خودکار کاربران جدید**: عضویت خودکار حساب های کاربری تازه ثبت نام شده در چت های عمومی

## تب سرویس‌ها

کارت‌های سلامت برای سرویس‌های بک‌اند (ورکر مدیا، اتصال Telegram، درایور فضای ذخیره سازی):

- **Media worker**: وضعیت دسترسی به ورکر و وضعیت صف.
- **Telegram connection**: وضعیت اتصال اکانت Telegram برای کانال های ریموت همراه با قابلیت برقرار کردن اتصال.
- **Storage**: وضعیت درایور فعال ذخیره سازی.

## تب تنظیمات

پیکربندی تنظیمات زمان اجرا از طریق رابط کاربری (جایگزین اکثر متغیرهای `.env`):

### دسته‌ها

#### عمومی

- لاگ اشکال‌زدایی
- ثبت‌نام (سرور عمومی)

#### آپلود فایل

- قابلیت آپلود فایل فعال شده
- حداکثر اندازه فایل در هر آپلود
- حداکثر اندازه کل در هر پیام
- حداکثر فایل در هر پیام
- ترنسکد ویدئو فعال شده

#### نگهداری پیام

- دوره نگهداری فایل (روز)
- دوره نگهداری پیام متنی (روز)

#### محدودیت‌ها

- حداکثر طول پیام (کاراکتر)
- حداکثر طول نام کاربری
- حداکثر طول نام مستعار

#### رفتار کلاینت

- محدودیت‌های دریافت پیام
- اندازه صفحه پیام
- TTL کش
- بازه refresh لیست چت‌ها
- بازه health check اتصال
- تاخیر reconnect برای SSE
- حداکثر نتایج جستجو
- timeout پیام متنی pending
- timeout پیام فایلی pending
- بازه retry برای پیام‌های pending
- بازه بررسی وضعیت پیام‌های pending

#### ذخیره سازی (Object Storage و Worker)

- انقضای Presigned URL بر حسب ثانیه — نیازمند restart
- پیکربندی خودکار CORS برای bucket — نیازمند restart
- نشانی Worker خارجی برای مدیا (قابل خالی بودن، live)
- timeout fallback برای Worker بر حسب ms

#### Realtime (نیازمند restart)

- بازه heartbeat برای WebSocket بر حسب ms
- timeout برای heartbeat در WebSocket بر حسب ms

#### کانال ریموت

- قابلیت کانال ریموت فعال شده
- اجازه تغییر در رابط کاربری برای مالکان کانال
- اجازه گزینه استریم رسانه
- حالت tick
- پیکربندی polling و صف

#### پراکسی‌ها

- نشانی پراکسی برای تحویل push (قابل خالی بودن) — نیازمند restart
- نشانی Proxy برای Object Storage (قابل خالی بودن) — نیازمند restart
- نشانی پراکسی Telegram (قابل خالی بودن) — نیازمند restart
- نشانی پراکسی Songbird برای ارتباط سرور به سرور (قابل خالی بودن، live)

#### Calls

- تاگل اصلی تماس‌ها (live)
- تاگل تماس تصویری (live، در حالت خاموش بودن تاگل اصلی غیرفعال است)
- حداکثر مدت زمان تماس به دقیقه (۰ = بدون محدودیت) — نیازمند restart

#### Secrets (فقط مالک)

- secretهای سیستمی فقط‌خواندنی: secret مربوط به tick کانال ریموت، secret مربوط به webhook ورکر، توکن API ادمین. فقط برای مالک سرور قابل مشاهده است، نه ادمین‌ها.

:::info لغو توسط متغیرهای محیطی

[متغیرهای محیطی](./Environment-Variables.md) در `.env` بر تنظیمات دیتابیس اولویت دارند. فیلدهای قفل‌شده نشان‌دهنده لغو فعال توسط env هستند.

:::

## تب اقدامات

انجام وظایف مدیریت سیستم:

### عملیات دیتابیس

**پشتیبان‌گیری**
- آرشیو فعال MongoDB به‌صورت Extended JSON فشرده‌شده با gzip (`.json.gz`) و شامل رکوردهای دیتابیس و اطلاعات کلیدهای رمزگذاری است.
- متادیتای پیوست در دیتابیس است؛ فایل باینری محلی یا S3 به پشتیبان جدا نیاز دارد. آرشیوها را خصوصی نگه دارید.

**بازیابی**
- بازیابی آنلاین MongoDB، HTTP `409` و راهنمای CLI آفلاین برمی‌گرداند.
- تمام نویسندگان برنامه را متوقف کنید؛ سپس `npm --prefix server run db:restore -- --file ./backups/ouj.backup.json.gz --yes --offline` را اجرا کنید.
- پس از بازیابی و پیش از شروع ترافیک، `npm --prefix server run db:check` را اجرا کنید.

**بررسی دیتابیس**
- MongoDB از `VACUUM` مربوط به SQLite یا PostgreSQL استفاده نمی‌کند.
- از بررسی داده/ایندکس MongoDB و ابزارهای نگه‌داری provider استفاده کنید. فایل تاریخی `.db` یا `.dump` منبع ورود دادهٔ قدیمی است و آرشیو بازیابی بومی MongoDB نیست.

قالب پشتیبان، ورود داده و محدودیت‌های بازیابی در [دستورهای دیتابیس](./Database-Commands.md) و [MongoDB](./MongoDB.md) آمده است.

### کنترل سیستم

**بررسی نسخه**
- بررسی نسخه نصب‌شده فعلی
- مقایسه با آخرین نسخه GitHub
- بررسی در دسترس بودن به‌روزرسانی

**ریستارت سرویس**
- ریستارت سرور Songbird
- اعمال تغییرات در انتظار
- اتصال مجدد همه کلاینت‌ها

**توقف سرویس**
- توقف نرم سرور Songbird
- نیاز به شروع دستی از طریق systemd/Docker

:::warning نیازمندی‌های مجوز

کنترل سرویس (ریستارت/توقف) بسته به نوع استقرار به راه‌اندازی مناسب نیاز دارد:

- **Docker**: کانتینر `songbird` باید سوکت Docker را mount کرده باشد (`/var/run/docker.sock`). این در `docker-compose.yaml` پیش‌فرض گنجانده شده است. متغیر محیطی `SONGBIRD_CONTAINER_NAME` به اپلیکیشن می‌گوید کدام کانتینر را هدف قرار دهد (پیش‌فرض: `songbird`). به [نصب از طریق Docker](./Installation-Docker.md#کنترل-سرویس-در-پنل-مدیریت) مراجعه کنید.
- **Systemd**: کاربر سرویس باید مجوزهای `sudo` برای `systemctl` داشته باشد. به [عیب‌یابی](./Troubleshooting.md#مشکلات-پنل-مدیریت) مراجعه کنید.

:::

### منطقه خطرناک

**پاک‌کردن همه پیام‌ها**
- حذف همه پیام‌ها از همه چت‌ها
- ساختار چت و عضویت حفظ می‌شود
- حساب‌های کاربری حفظ می‌شوند
- عملیات غیرقابل‌بازگشت

**بازنشانی دیتابیس**
- کاربران، چت‌ها، پیام‌ها، نشست‌ها و فایل‌های پیام ذخیره‌شده را پاک می‌کند، اما schema و تنظیمات زمان اجرا را نگه می‌دارد
- عملیات غیرقابل‌بازگشت

:::danger اقدامات غیرقابل‌بازگشت

اقدامات منطقه خطرناک قابل بازگشت نیستند. همیشه قبل از ادامه یک پشتیبان ایجاد کنید.

:::

## غیرفعال سازی پنل مدیریت

برای غیرفعال سازی کامل پنل مدیریت:

```bash
# در فایل .env
ADMIN_PANEL=false
```

هنگام غیرفعال بودن:
- دکمه Admin از رابط کاربری مخفی میشود
- نقاط پایانی API مدیریت کد 403 بازمیگردانند
- حساب های موجود owner و admin باقی میمانند اما نمیتوانند به پنل دسترسی داشته باشند

## نکات امنیتی

- API مدیریت از یک توکن احراز هویت جداگانه استفاده می کند (`ADMIN_API_TOKEN`)
- در اولین اجرا به صورت خودکار تولید و در `.env` ذخیره میشود (یا از طریق متغیرهای محیطی در سرویس های PaaS مانند Render تنظیم میشود)
- نقطه پایانی ارتقای مدیریت اضطراری (`/api/admin/claim`) توکن ها را با استفاده از مقایسه های ایمن زمانی (timing-safe) بررسی کرده و امنیت HTTPS/localhost را الزامی میکند
- نقاط پایانی مدیریت به طور پیشفرض محدود به localhost یا کاربران مدیریت احراز هویت شده هستند
- همه اقدامات مدیریتی و ارتقاهای اضطراری برای ردیابی ممیزی ثبت میشوند
- محدودیت نرخ اعمال میشود (1000 req/15min از نسخه v0.11.1)

## جایگزین CLI

فرمان‌های بومی MongoDB مدیریت حساب، گفتگو و فایل را پوشش می‌دهند. از ریشهٔ مخزن، پیش از تغییر داده نحو آرگومان‌ها را ببینید:

```sh
npm --prefix server run db:user:create -- --help
npm --prefix server run db:user:edit -- --help
npm --prefix server run db:user:delete -- --help
npm --prefix server run db:chat:create -- --help
npm --prefix server run db:chat:edit -- --help
npm --prefix server run db:file:delete -- --help
npm --prefix server run db:check
npm --prefix server run db:inspect -- --limit 25
```

تغییرات کاربر، گفتگو و فایل از سرور محلی در حال اجرا با `ADMIN_API_TOKEN` استفاده می‌کنند، یا پس از توقف همهٔ نویسندگان به `--offline` نیاز دارند. حذف علاوه بر آن `--yes` یا `-y` می‌خواهد. بازیابی کل دیتابیس همیشه به مسیر آرشیو و `--yes --offline` نیاز دارد و از پنل MongoDB در حال اجرا انجام نمی‌شود.

مرجع کامل CLI در [دستورهای دیتابیس](./Database-Commands.md) و پشتیبان‌گیری و انتقال در [MongoDB](./MongoDB.md) آمده است.
