# دستورهای دیتابیس

پایگاه دادهٔ فعال گفتگوی اوج MongoDB است. دستورهای نگه‌داری Node.js/npm زیر از ریشهٔ مخزن و بدون wrapper مبتنی بر Bash اجرا می‌شوند. ابتدا `MONGODB_URI` و `MONGODB_DATABASE` را در تنظیم خصوصی مشخص کنید؛ [MongoDB](./MongoDB) را ببینید.

## مرجع سریع

| دستور | کاربرد |
|---|---|
| `npm --prefix server run db:check` | بررسی اتصال و گزارش آمار دیتابیس، از جمله تعداد ایندکس‌ها. |
| `npm --prefix server run db:migrate` | ساخت/بررسی collection و ایندکس MongoDB؛ مایگریشن SQL قدیمی اجرا نمی‌شود. |
| `npm --prefix server run db:inspect -- --limit 25` | نمایش تعداد و نمونهٔ محدود متادیتای کاربران، گفتگوها و فایل‌ها. |
| `npm --prefix server run db:user:inspect -- --limit 25` | بررسی متادیتای کاربران با حذف هش رمز عبور. |
| `npm --prefix server run db:chat:inspect -- --limit 25` | بررسی متادیتای گفتگو و عضویت. |
| `npm --prefix server run db:file:inspect -- --limit 25` | بررسی متادیتای پیوست و آواتار و حجم ثبت‌شدهٔ فایل. |
| `npm --prefix server run db:help` | راهنمای فعلی دستورهای نگه‌داری بومی. |
| `npm --prefix server run db:backup -- --file ./backups/ouj.backup.json.gz` | نوشتن آرشیو gzip Extended JSON برنامه. |
| `npm --prefix server run db:restore -- --file ./backups/ouj.backup.json.gz --yes --offline` | بازیابی آرشیو با برنامهٔ متوقف‌شده. |
| `npm --prefix server run db:import-sql -- --source ./backups/songbird.db --dry-run` | بررسی SQLite قدیمی پیش از ورود. |
| `npm --prefix server run db:import-sql -- --postgres --dry-run` | بررسی PostgreSQL قدیمی با تنظیم `LEGACY_POSTGRES_URI`. |

مسیرها نمونه‌اند. پوشهٔ پشتیبان قابل‌نوشتن و خارج از دیسک موقت کانتینر انتخاب کنید. دیتابیس از تنظیم محیط MongoDB می‌آید، نه `DATA_DIR`، `DB_CLIENT` یا نام فایل `.db`.

## بررسی دیتابیس

```sh
npm --prefix server run db:check
```

پس از راه‌اندازی اولیه، ورود دادهٔ قدیمی یا بازیابی آفلاین بررسی را اجرا کنید. نتیجهٔ واقعی دستور را بخوانید؛ اتصال موفق به‌تنهایی به معنی تأیید همهٔ رفتارهای برنامه یا بار محیط تولید نیست.

## پشتیبان‌گیری

```sh
npm --prefix server run db:backup -- --file ./backups/ouj.backup.json.gz
```

آرشیو شامل رکوردهای MongoDB و اطلاعات کلیدهای رمزگذاری به‌صورت Extended JSON فشرده با gzip است؛ فایل SQLite با پسوند `.db`، PostgreSQL با پسوند `.dump` یا آرشیو `mongodump` نیست. آن را خصوصی نگه دارید و تنظیمات محیط و رمزگذاری متناظر را حفظ کنید.

متادیتای فایل در MongoDB است، اما باینری پیوست و آواتار در provider محلی یا S3 می‌ماند. از volume یا اشیای راه‌دور جداگانه پشتیبان بگیرید. برای نقطهٔ بازیابی هماهنگ، نوشتن‌ها را متوقف کنید یا از روش پشتیبانی‌شدهٔ دیتابیس و provider استفاده کنید؛ آرشیو برنامه وعدهٔ snapshot هم‌زمان کل خوشه نیست.

## بازیابی آفلاین

ابتدا تمام نمونه‌های برنامه و ورکرهایی را که به مقصد می‌نویسند متوقف کنید:

```sh
npm --prefix server run db:restore -- --file ./backups/ouj.backup.json.gz --yes --offline
npm --prefix server run db:check
```

`--yes` تأیید عملیات و `--offline` تأیید توقف نویسندگان است. خود CLI سرویس‌ها را متوقف نمی‌کند. بازیابی آنلاین MongoDB در پنل مدیریت، HTTP `409` و راهنمای آفلاین برمی‌گرداند. برنامه را پس از بررسی رکوردها، فایل‌ها و کلیدهای لازم اجرا کنید.

قالب `.json.gz` برنامه با snapshot ارائه‌دهنده یا آرشیو BSON ابزارهای `mongodump` و `mongorestore` متفاوت است. برای هر قالب از ابزار بازیابی متناظر استفاده کنید.

## ورود دادهٔ SQL قدیمی

SQLite و PostgreSQL فقط منبع خواندنی انتقال داده‌اند؛ گزینهٔ اجرای فعال نیستند و هنگام خالی‌بودن `MONGODB_URI` به‌عنوان fallback استفاده نمی‌شوند.

1. نصب قدیمی را متوقف و دیتابیس، آپلودها و کلیدهای رمزگذاری آن را حفظ کنید.
2. یک دیتابیس MongoDB جدید و خالی به‌عنوان مقصد تنظیم کنید.
3. اجرای آزمایشی را انجام دهید، شمارش‌ها و اعتبارسنجی را بررسی و سپس صریحاً اعمال کنید:

```sh
npm --prefix server run db:import-sql -- --source ./backups/songbird.db --dry-run
npm --prefix server run db:import-sql -- --source ./backups/songbird.db --apply
```

برای PostgreSQL، مقدار `LEGACY_POSTGRES_URI` را در محیط خصوصی قرار دهید و از پرچم بدون آرگومان دارای رمز استفاده کنید:

```sh
npm --prefix server run db:import-sql -- --postgres --dry-run
npm --prefix server run db:import-sql -- --postgres --apply
```

4. پیش از جابه‌جایی ترافیک، `db:check` را اجرا و حساب‌ها، دسترسی‌ها، تعداد پیام‌ها، UUIDها، محتوای رمزگذاری‌شده و دسترسی فایل را بررسی کنید.

ورود داده، باینری آپلودها را کپی نمی‌کند، نصب منبع را تأیید نمی‌کند و نیاز به پشتیبان بازگشت را از بین نمی‌برد. مایگریشن SQL و `VACUUM` مربوط به نصب‌های قدیمی‌اند، نه نگه‌داری MongoDB. [راهنمای کامل انتقال](./MongoDB#ورود-داده-از-نصب-sql-قدیمی) را ببینید.

## مدیریت دیگر

برای عملیات حساب، گفتگو و فایل از [پنل مدیریت](./Admin-Panel) یا CLI بومی Node.js استفاده کنید. فرمان‌های زیر از `server/scripts/mongo-cli.js` و بدون پوشش Bash اجرا می‌شوند. با `--help` هر فرمان، نحو فعلی آن را ببینید؛ نمایش راهنما به URI فعال MongoDB نیاز ندارد.

| فرمان‌ها | آرگومان / رفتار |
|---|---|
| `db:user:create`، `db:user:edit` | ایجاد با `--username`، `--password` و `--nickname` یا `--role` اختیاری؛ ویرایش با شناسه یا نام کاربری و سپس فیلدهای تغییرکرده. |
| `db:user:ban`، `db:user:verify` | انتخاب کاربر با شناسه یا نام کاربری؛ وضعیت مربوطه جابه‌جا می‌شود مگر مقدار صریح وارد شود. |
| `db:chat:create`، `db:chat:edit` | ایجاد با `--name`، `--username`، `--owner` و `--type` اختیاری با مقدار `group` یا `channel`، یا `--users alice,bob`؛ ویرایش با شناسه یا نام کاربری گفتگو. |
| `db:chat:add`، `db:chat:verify` | افزودن اعضا با `CHAT --users alice,bob` یا `CHAT --all`؛ تأیید با انتخاب گفتگو. |
| `db:user:delete`، `db:chat:delete`، `db:file:delete` | انتخاب کاربر و گفتگو با شناسه یا نام کاربری، و فایل با شناسه. حذف به `-y` یا `--yes` نیاز دارد. |
| `db:user:generate`، `db:message:generate` | ایجاد کاربر نمایشی با `--count` و `--password`، یا پیام با `--chat`، `--user` و `--count`. |

از ریشهٔ مخزن، راهنما را ببینید یا صف یک کانال ریموت موجود را ادامه دهید:

```sh
npm --prefix server run db:user:edit -- --help
npm --prefix server run db:chat:edit -- your_channel --resume-queue
```

هنگام اجرای سرور محلی، تغییرات کاربر، گفتگو و فایل از `/api/admin/db-tools` آن استفاده می‌کنند و به `ADMIN_API_TOKEN` در تنظیمات خصوصی نیاز دارند. هنگام توقف سرور، همهٔ نویسندگان دیگر را متوقف کنید و برای مدیریت مستقیم MongoDB گزینهٔ `--offline` را اضافه کنید. حذف آفلاین به هر دو گزینهٔ `--offline` و `--yes` نیاز دارد؛ این گزینه‌ها سرویس را متوقف نمی‌کنند. عملیات کل دیتابیس یعنی `db:reset`، `db:delete` و `db:restore` همیشه `--yes --offline` می‌خواهند. `--force` جای این تأییدها را نمی‌گیرد.

خروجی بررسی شامل متادیتای حساب و گفتگو است؛ آن را خصوصی نگه دارید. این خروجی محدود به تعداد نیست، هرچند هش رمز عبور از نمونهٔ کاربران حذف می‌شود. حذف فایل و پشتیبان‌گیری دیتابیس عملیات جداگانه‌اند؛ آرشیو دیتابیس شامل باینری اشیای provider رسانه نیست.

`remote:configure` همچنان ابزار تعاملی تنظیم محیط و Telegram است؛ [راه‌اندازی کانال ریموت](./Remote-Channel-Setup) را ببینید. فرمان‌های نگهداری ذخیره‌سازی راهنمای مستقل دارند و فرمان انتقال SQL به MongoDB نیستند.

برای ابعاد یا مدت گم‌شده در آپلودهای **محلی** موجود، `npm --prefix server run db:backfill -- --limit=1000` رسانهٔ محلی را می‌خواند و متادیتا را از طریق facade مربوط به MongoDB به‌روز می‌کند. بررسی ویدیو به `ffprobe` نیاز دارد. این فرمان دانلود باکت، ورود SQL یا اجرای آزمایشی نیست؛ پشتیبان را حفظ کنید و پیش از نگهداری، نویسندگان را متوقف کنید.

برای چیدمان قدیمی کلیدهای S3، برنامه را متوقف و نتیجهٔ `npm --prefix server run storage:migrate -- --dry-run` را بررسی کنید. اجرای اعمال تغییر با `npm --prefix server run storage:migrate -- --yes` است؛ اشیای تأییدشده را به `uploads/messages/*` و `uploads/avatars/*` کپی می‌کند، متادیتای MongoDB را بازنویسی و سپس کلیدهای قدیمی متناظر را حذف می‌کند. این ابزار `--dry-run`، `--yes` یا `-y` و `--help` می‌پذیرد؛ سرور محلی در حال اجرا را رد می‌کند و به گزینهٔ `--offline` فرمان‌های دیتابیس نیاز ندارد. ابتدا از رکوردها و اشیا پشتیبان بگیرید و پیش از اجرای مجدد برنامه، خطاهای جزئی کپی یا حذف را بررسی کنید.

در Docker، دستور را در کانتینری با محیط صحیح و دسترسی به مسیر آرشیو اجرا کنید. بازیابی آفلاین از کانتینر یا فرایند نگه‌داری جداگانه و با نویسندگان متوقف‌شده انجام شود، نه از API در حال اجرا.
